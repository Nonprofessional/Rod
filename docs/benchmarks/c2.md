# C2 tasking and implant management benchmark note

The action stage's operator half (architecture.md Sec 5, Sec 10): how an
operator sees implants, issues tasking, and consumes results. Rod ships
the full loop today -- profiles baked at generation (Sec 5.1), the
queued task lifecycle with per-verb OPSEC posture (Sec 7, Sec 10.3),
child-implant derivation, and the browser and web-shell classes beside
the standard implant (Sec 5.2). ADR-012 names the benchmark set: Sliver,
Mythic, Cobalt Strike, Havoc.

## Adopt

- **Schema-rendered tasking forms** (Mythic). An unbounded verb catalog
  cannot carry hand-built forms, and Mythic's proof is that the operator
  never notices the form is generic. Already decided as the
  parameter-schema third of the contract trilogy (Sec 15.2, ADR-003):
  the UI renders the tasking form from the verb's declared schema and
  knows nothing about the module behind it. Lands in the UI over the
  existing descriptor metadata.
- **Typed task products in generic panels** (Mythic). Credentials,
  artifacts, and the file browser as panels over any agent's output
  prove the interaction: results declare what they produced, and views
  follow. Rod's output taxonomy (ADR-003) carries it further -- process
  lists, enumeration structures -- with the same rule: a module that
  types its output poorly degrades to plain text and the UI keeps
  working.
- **Per-implant compatibility surfaced at task time** (Mythic's
  per-callback command hints). A command an implant class cannot run
  reads disabled with a reason, never fails at run time. The manifest
  compatibility matrix (ADR-009) is the mechanism, rendered by the same
  schema-driven UI.
- **The shared attributed event stream as the main screen** (Cobalt
  Strike's event log, Mythic's operation feed). Every operator works the
  same stream and every entry carries its author. Adopted as the
  timeline-main-screen decision (ADR-013) with collaboration riding it
  (ADR-005) and one Rod divergence: comments and chat ride the timeline
  but never enter the hash chain.
- **Implant parentage rendered as a graph** (Cobalt Strike's pivot
  graph, Mythic's callback graph). Lateral movement reads as a picture;
  Rod ships parentage (Sec 5.2) and the topology render is an optional
  module (ADR-013), not a primary navigation.
- **Saved, re-runnable build configurations** (Sliver profiles, Cobalt
  Strike listener and stager configurations). Rebuilding a known-good
  implant must never re-ask its parameters. Rod's build profiles (Sec
  5.1, Sec 6) already answer; the benchmark sets the interaction bar:
  one action from profile to artifact.
- **Traffic-shape posture carried by the profile, not the binary**
  (Cobalt Strike malleable C2 profiles). The operator tunes egress
  indicators per engagement without tool surgery, and the tuning is
  data an engagement can review. Rod's landing is the build profile
  (Sec 5.1) plus the payload transform seam (Sec 13) -- the shape is
  visible at build time, not mutated after it.
- **Keyboard-first tasking speed** (Havoc's console). The tasking loop
  is the operator's entire day; the command palette and keyboard-first
  tasking of ADR-013 are the adoption.

## Skip

- **The multi-container deployment** (Mythic). RabbitMQ, per-agent
  Docker containers, and a compose stack are the field's single largest
  adoption friction, and the standing constraint closes the door:
  teamserver and PostgreSQL, nothing standing beside them (Sec 15). The
  module ecosystem keeps Mythic's two real decoupling axes -- transport
  providers, implant languages -- without the bus (Sec 15.2).
- **The fat desktop client** (Cobalt Strike's Java client, Havoc's Qt
  client, Sliver's desktop GUI). Three clients mean three upgrade tails
  and one pivot each away from the server's collaboration model. The
  browser UI is Rod's single operator surface (Sec 4.3); multiplayer is
  the server's concern.
- **A bespoke extension dialect** (Aggressor, Havoc's Python
  extensions). An embedded scripting language is a permanent
  maintenance liability and splits extension work away from the module
  contracts. Rod's answers are the module seams (Sec 15.1) and the
  versioned API with official SDKs (ADR-006).
- **gRPC operator client libraries** (Sliver). Client-library coupling
  to server internals freezes server evolution; the contract-first
  `/api/v1` with OpenAPI as its source replaces them (ADR-006).
- **An interactive keystroke channel beside the task queue** (Sliver
  live sessions, Cobalt Strike's shell mode). A second, live channel
  duplicates tasking semantics and splits the audit story -- every
  keystroke either enters the chain or it does not. Rod keeps one
  queue: shell rides the ordinary tasking lifecycle with the same
  evidence posture (Sec 10.3), and queue feedback -- per-implant
  check-in posture, task state -- carries the liveness the operator
  actually needs from a session.
- **Trust-by-repository-location extension installs** (Sliver's
  Armory). Installing extensions by GitHub reference makes the host
  vouch for the code. Rod's registry carries signed manifests verified
  at install (ADR-002, ADR-009): signatures, not platform vouching.

## Divergences Rod already owns

Engagement isolation by construction, the hash-chained audit, and
per-verb OPSEC labeling are three facts no benchmark tool carries:
Mythic scopes by operation ACLs rather than tenancy, none of the four
chains evidence tamper-evidently, and OPSEC posture is folklore rather
than labeled data. Where an entry touches attribution, evidence, or
OPSEC, Rod is already ahead and the benchmark sets only the interaction
bar.
